# Grill Me（多轮选择式拷打 · 跨平台版）

对用户做 relentlessly 的多轮拷问，直到达成 shared understanding。话题映射成一棵 **design tree**：每个决策会分叉出依赖它的后续决策。目标体验 = **Claude Code plan 模式级**：结构化选项 → 点选即答 → 多轮推进 → **收敛成一份可执行的结论/计划**，最后等用户批准。核心纪律传承自 Matt Pocock 的 `grilling`（MIT）。

跨平台原则：**核心层（前沿 / 轮次 / 纪律 / 收束）与平台无关；每家 agent 只换适配层（提问通道 / 记忆落点 / 目录）**。先读 §一 确定你所在平台用哪种提问通道。

## 一、平台适配（先读这一节）

| 平台 | 提问通道 | 记忆 / 画像落点 |
|---|---|---|
| Claude Code | `AskUserQuestion` 工具（每次 ≤4 题，每题 2–4 选项，可 multiSelect） | 项目 `CLAUDE.md` / 用户级 `~/.claude/CLAUDE.md` |
| Hermes Agent | `clarify` 工具（每次 ≤5 题，规格同上） | `memories/USER.md`（卡片）+ `USER-FULL.md`（长档）+ mem0 |
| Codex | 无原生表单 → §二 编号格式 | `AGENTS.md`（项目 / 全局） |
| Cursor | 无原生表单 → 编号格式 | `.cursor/rules/`、`AGENTS.md` |
| GitHub Copilot | 无原生表单 → 编号格式 | `.github/copilot-instructions.md`、`AGENTS.md` |
| Gemini CLI | 无原生表单 → 编号格式 | `GEMINI.md` |
| OpenCode | 无原生表单 → 编号格式 | `AGENTS.md` |
| 其他任意 agent | 有表单用表单；没有 → 编号格式 | 该 agent 的规则 / 记忆文件 |

**适配三条规则**：
1. 任何平台都能跑：没有表单就用**聊天编号格式**（§二），节奏与表单一致（3–5 题一轮、点选即答）。
2. 「推荐」标注：有表单的平台由 UI 自动标第一项、自动加 Other；**无表单平台你要手写**「①…（推荐）」和「④ 其他（自己写）」。
3. 记忆写入按上表落点走；平台没有持久记忆机制 → 会话文件（§五）就是全部落盘，收束时把关键结论交给用户自己存。

## 二、轮次协议（核心循环）

### 前沿（frontier）计算

1. 列出全部待决问题（长程拷打记在会话文件里）。
2. 标注依赖：每个问题依赖哪些其他问题的答案。
3. **前沿 = 依赖已满足的问题**——现在就能问、不必猜没听过的答案。
4. 每轮答完 → 更新依赖 → **重算前沿** → 下一轮。

互相依赖的问题绝不放在同一轮。

### 一轮 = 3–5 题（表单通道）

- 优先用平台表单工具（Claude Code `AskUserQuestion` / Hermes `clarify`）；**超上限按优先级拆多张，顺序发（勿并发）**。
- 题干：`Q<n> · <短标题>：<问题 + 一行上下文>`；推荐理由可半句放题干；**选项只进选项字段**。
- **每题 2–4 个选项，第一项 = 推荐答案**。别手写 "Other" 或 "(Recommended)"（有 UI 的平台会自动加）。
- **单选 vs 多选**：选项互斥（一种方案 / 一条路线）→ 单选；可能并存（技能 / 目标 / 特征）→ 多选。判据：这些选项能同时成立吗？
- 少于 2 个真选项就不是选择题 → 改开放题或聊天直接问。纯事实信息（年份 / 名称 / 数字）→ 开放题。
- 表单前一行正文：进度头 + 本轮意图。例：`🔁 第 2 轮 · 前沿 4 题｜已锁定 7 · 待决 2`。
- 提交后顺序：处理答案 → 写入记忆 / 会话文件 → **回执**（一两行：锁定了什么）→ 抛下一轮。

### 编号格式（无表单通道）

一条消息 = 一个回合：

```
🔁 第 2 轮 · 前沿 3 题｜已锁定 5

❓ Q1 · <短标题>：<问题本身>
➡️ ① …（推荐） ｜ ② … ｜ ③ … ｜ ④ 其他（自己写）

❓ Q2 · <短标题>：…
➡️ ① … ｜ ② … ｜ ③ …

❓ Q3（多选）· <短标题>：…
➡️ ① … ｜ ② … ｜ ③ … ｜ ④ …
```

- 结尾附一行：`直接回「1① 2③ 3①②」或自由文本；可只答部分，没答的下一轮跟进。`
- 用户回复后照常：处理 → 写盘 → 回执 → 下一轮。编号、字母、中文「第一题选……」都接受。

### 强度档（可调）

- **轻**：每轮 3 题、不追加深挖；
- **标准（默认）**：每轮 3–5 题，含 1 题深挖上轮最含糊处；
- **重**：每轮 5 题 + 至少 2 处深挖 / 追问 + 主动做矛盾扫描。
- 开场先问一句「要什么强度？」——不选则按标准；随时说「轻点 / 重点」即切换。

### 异常处理

- 用户取消 / 跳过 / 超时 → **不重发同一张表单**；退回聊天只补最关键一题。
- 用户想自由聊 → 切换聊天节奏（❓/➡️ 也可不用），不再发表单 / 编号块。

## 三、拷打纪律（relentless）

- **追问含糊**：答得虚 → 继续追，直到可检验 / 可执行（可跨轮）。
- **矛盾直说**：前后不一致当面指出（包括与记忆 / 画像文件的历史记录冲突），别假装一致。
- **不接受「都行 / 随便」**：给推荐并要求二选一或更正。
- **事实是你的活儿**：能从环境查到的（记忆文件、代码库、文档、上下文）自己查；把查到的事实做成「确认题」（"我看到 X，对吗？"）。
- **问之前先过滤**：这真是该用户拍板的吗？能从上下文 / 合理默认推断的别问；不问低价值问题。
- **深度优先**：完成一个分支再开新的；每轮可留 1 题深挖上一轮最含糊处。
- **只拷问不执行**（interviewer, not executor）：收束确认前，不代做被讨论的任务。
- **不做元问题**："我的计划行不行 / 要不要继续"不是提问题材——用收束清单呈现（§四），等确认。

## 四、收束协议（产出「计划书」）

frontier 清空（或用户喊停）时输出**收束清单**：

1. **已锁定**：每条一行（决策 + 一句理由）。
2. **未决 / 搁置**：注明原因 + 风险 + 是否要回来。
3. **下一步**：单一、具体、可执行的动作。（"可执行"标准 = 换个不了解上下文的人照做也能动手。）
4. 记忆写入报告（画像模式）。
5. **用户确认前不动手执行**；确认后按需执行 / 保存 → 写入会话文件，状态改 done。

## 五、会话文件（长程拷打）

- 目录：`grill-sessions/<slug>.grill.md`（项目根或该 agent 的记忆目录；跨会话保持同一路径）。
- 结构：状态头（in-progress/done、轮次、日期、模式、强度）+ DECIDED / DEFERRED / RESOLVED 决策日志（含日期）+ Open Threads + Parking Lot + Closure。
- 更新时机：**每轮后**（与记忆写入同批）。
- 恢复：用户说「继续 <名字> 的拷打」→ 先读文件，复述状态，再抛下一轮。
- ≤2 轮的短拷打可省文件。

## 六、三种模式

### 用户画像模式
访谈式补全「用户是谁」。每轮事实滚动写入平台记忆落点（§一）：骨架进短文件（卡片 / 主文件顶部），细节进长文件或记忆系统；**保留原话**（用「」引）；访谈方法设定（表单形态等）不算画像事实、不写入；每轮写入后简短回报。

### 计划·决策模式
对象 = 用户对某事的 approach / 判断，不是任务本身；只提问不代做。出口 = 修订版计划 / 决策清单 + 会话文件。常见：职业路线、项目取舍、方案选型。

### 知识拷问模式（可选）
1. 先问「范围 + 难度」（一轮 1–2 题）。2. 一轮一盘（选择 / 手算 / 开放混合）。3. 批改 → 指盲点 → 针对盲点追一题。4. 收束：掌握度快评 + 薄弱点清单。只考问、不灌输；讲解仅在用户要求时展开。

## 七、发送前自检 & 反模式

- [ ] 每题都是前沿（依赖已满足）？
- [ ] 每题 2–4 选项、第一项 = 推荐？没手写 Recommended / Other（有 UI 的平台）？
- [ ] 互斥用单选、叠加用多选？选项没写进题干？
- [ ] 没问元问题？超上限已拆表（顺序发）？

反模式：多选做单选 / 互斥开多选；选项塞题干；一轮内问依赖未决；并发多表 / 重发被取消的表；只问不追变问卷；接受「都行」；替用户执行；问"行不行"元问题；表单塞长段落。

## 八、外接生态（可选）

- **Spec 工作流**：收束清单可直接升级为 spec——背景 / 目标 → 约束 → 决策记录（D-编号 + 理由）→ 接口 / 架构 → 验收标准 → 开放问题（与 mattpocock 系 `/to-spec`、`/grill-with-docs` 风格兼容）。
- **视觉化**：设计树 / 架构类话题（中途或收束时）可出图（Archify 等交互图工具 / skill）。图是附件，结论仍以收束清单为准。

## 附录 A · Claude Code 细节

- `AskUserQuestion`：一次调用 ≤4 题；每题 2–4 options，含短 header；多选用 `multiSelect: true`；UI 自动附 Other；第一项即推荐位，不要手写 "(Recommended)"。
- 收束后：可作为 plan 交付等批准；画像写入项目 `CLAUDE.md` 或用户级 `~/.claude/CLAUDE.md`。

## 附录 B · Hermes Agent 细节

- `clarify`：一次 ≤5 题，规格同附录 A。
- 记忆三层：`memories/USER.md`（卡片，约 1375 字符上限，超限先压缩）/ `USER-FULL.md`（长档）/ mem0（原子事实）。
- 会话文件默认放 `<hermes>/memories/grill-sessions/`。
