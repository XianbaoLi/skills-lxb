# Grill Me（多轮选择式拷打 · 跨平台版）

把话题组织成有依赖的决策树，多轮选择与深挖，收敛成可复核的结论或计划。借鉴 plan 式交互，但不冒充原生 Plan Mode：用户先理解再选择，结论确认不替代执行审批。方法参考 Matt Pocock 的 `grilling`（MIT）。

跨平台原则：**核心层（前沿 / 轮次 / 纪律 / 收束）与平台无关；每家 agent 只换适配层（提问通道 / 记忆落点 / 目录）**。先读 §一 确定你所在平台用哪种提问通道。

## When to Use（启用边界）

**仅在当前用户明确要求开始或继续多轮访谈时启用**：例如「拷打我这个方案」「逐轮帮我理清，边问边讲」或明确调用本 skill。

- **加载不等于启动访谈**：安装、修改、解释或排查本 skill 时，可以阅读本文，但不得开始提问、选强度或写入画像。
- **历史记忆、引用文本或技能名称的出现不是启动指令**；普通计划、代码修改、权限审批不自动切入。无需逐字匹配口令，但必须有当前的访谈意图。
- 收束、喊停或切换任务后退出访谈；只有明确要求恢复该访谈才继续。普通澄清问题仍可按宿主日常方式问，不必套本协议。

## 审批边界（所有模式先遵守）

**理解 ≠ 选择 ≠ 授权 ≠ 执行**。本 skill 是访谈方法，不是宿主的 Plan Mode、权限系统或审批开关。

- **clarify / AskUserQuestion 不是审批工具**：选方案、表示听懂、确认收束都不等于允许安装、改文件、发布、删除或写入长期记忆。
- 把「你倾向哪个方案」与「允许对哪个目标做什么」分开；不得放进同一张偏好表单，用推荐项、默认勾选或用户答题推定批准。
- **跳过审批题不代表同意或拒绝**；取消、超时、沉默均不产生授权。该新增权限保持未决；已有许可仍按原范围有效。只补确实缺少的那个权限决定。
- **既有授权**仍按原范围有效：先核对当前任务与最新限制，不重复审批已允许的动作；「继续」只延续当前已授权阶段，不把只读调查升级成实现。
- 原生权限弹窗、计划批准及记忆/skill 写入审阅由宿主处理；不得替用户点击、自动代批、降低审批模式，或换工具/拆命令绕过拒绝。没有原生通道时，只能单独取得对象、动作、范围与风险明确的授权，不能假装平台已批准。
- 只读或只讨论时，不创建会话文件、不写长期记忆；仅在宿主明确允许的记录位置保存。记忆规则由宿主和用户原有约定控制，本 skill 不新增写入权限；草稿、待审、已应用必须区分。
- 收束只确认讨论结论；执行需有相应授权并经过宿主要求的审批，完成后仍需验证，不能把访谈结束记成任务已完成。

## 一、平台适配（先读这一节）

| Codex | 若当前模式暴露 `request_user_input` 则按其 schema，否则聊天 | 用户指定的私有记录；不默认写 AGENTS.md |
| Cursor | 有可用提问工具则使用，否则编号聊天 | 用户允许的记忆位置 |
| GitHub Copilot | 有可用提问工具则使用，否则编号聊天 | 用户允许的记忆位置 |
| Gemini CLI | 有可用提问工具则使用，否则编号聊天 | 用户允许的记忆位置 |
| OpenCode | 若暴露 `question` 则按其 schema，否则聊天 | 用户允许的记忆位置 |
| 其他任意 agent | 有表单用表单；没有 → 编号格式 | 该 agent 的规则 / 记忆文件 |

**适配三条规则**：
1. 不根据平台名字断言一定有/没有表单；只用当前真实暴露的工具。没有时用编号聊天，不能为使用表单而擅自切换执行/审批模式。
2. 推荐标注与 Other 依平台 schema；Hermes UI 自动附加时不重复。聊天可写有理由的推荐，但必须允许自由文本和暂不决定，不给个人事实安上推荐答案。
3. 持久化服从已有授权、原生审批与隐私范围；无权落盘时只在当前对话呈现结论，不自行创建文件。

## 二、轮次协议（核心循环）

### 前沿（frontier）计算

1. 列出全部待决问题（长程拷打记在会话文件里）。
2. 标注依赖：每个问题依赖哪些其他问题的答案。
3. **前沿 = 依赖已满足的问题**——现在就能问、不必猜没听过的答案。
4. 每轮答完 → 更新依赖 → **重算前沿** → 下一轮。

互相依赖的问题绝不放在同一轮。

### 每轮按理解负担选 1–5 题（表单通道）

- 优先用平台表单工具（Claude Code `AskUserQuestion` / Hermes `clarify`）；**超上限按优先级拆多张，顺序发（勿并发）**。
- 题干：`Q<n> · <短标题>：<问题 + 一行上下文>`；推荐理由可半句放题干；**选项只进选项字段**。
- 选择题通常 2–4 项，并服从实际工具 schema。推荐必须有理由，不能把个人事实、身份或偏好当成有标准答案；必要时用开放题。Hermes 的推荐/Other 由 UI 生成；其他平台按真实 schema 处理，不假设所有 UI 相同。
- **单选 vs 多选**：选项互斥（一种方案 / 一条路线）→ 单选；可能并存（技能 / 目标 / 特征）→ 多选。判据：这些选项能同时成立吗？
- 少于 2 个真选项就不是选择题 → 改开放题或聊天直接问。纯事实信息（年份 / 名称 / 数字）→ 开放题。
- 表单前一行正文：进度头 + 本轮意图。例：`🔁 第 2 轮 · 前沿 4 题｜已锁定 7 · 待决 2`。
- 提交后：区分理解、偏好和授权 → 仅在允许时记录（待审须标注）→ 一两行回执 → 重算前沿；不懂则先讲解，不直接追加问卷。

### 编号格式（无表单通道）

一条消息 = 一个回合：

```
🔁 第 2 轮 · 前沿 3 题｜已锁定 5

❓ Q1 · <短标题>：<问题本身>
➡️ ① …（推荐） ｜ ② … ｜ ③ … ｜ ④ 其他（自己写）

❓ Q2 · <短标题>：…
➡️ ① … ｜ ② … ｜ ③ …

❓ Q3（多选）· <短标题>：…
➡️ ① … ｜ ② … ｜ ③ … ｜ ④ …
```

- 结尾附一行：`直接回「1① 2③ 3①②」或自由文本；可只答部分，没答的下一轮跟进。`
- 用户回复后按同一边界处理：允许时记录 → 回执 → 下一轮；编号、字母、中文描述、只答部分或求讲解都接受。

### 先教后问（Teach → Check → Decide）

- **理解也是前置条件**：用户不知道概念或无法比较后果时，这题尚未进入可决策前沿。不要把术语换个说法继续逼选。
- 提问前用白话说明「在决定什么、为什么现在要问、会影响什么」；首次出现的术语解释含义，选项写实际后果，不让用户先懂缩写才能答。
- 用户说「没懂 / 不知道区别 / 先教我」或明显答非所问时，**讲解期间暂停整批问题**，先做最小讲解：**术语白话 → 一个具体例子 → 选项的后果**（收益、代价、不确定性）。仍不懂再换例子、示意图或分步推导，不能只重复定义。
- 先确认能否比较选项；可用一句生活化核对题，但不强制复述、考试或每题问「懂了吗」。用户说可以继续时，只恢复 1 题，把抽象技术选型改成用户能判断的需求。
- 始终提供「先讲解 / 暂不决定 / 跳过」路径；表单有空位可作选项，否则在表单前说明可用 Other 或聊天提出，不突破选项上限。不把「先讲解」标成方案 A。
- **不懂不是偏好**，听完例子不等于选定方案；不得把学习中的猜测、试答或暂不理解写成长久画像，也不把求助当成同意推荐方案。
- **强度与讲解深度独立**：重档增加检验和深挖，不增加术语门槛；轻档也能完整讲解。用户熟悉时直接问，不强行上课。

### 强度档（可调）

- **轻**：通常 1–3 题，少追问；**标准**：通常 3–5 题，深挖最含糊的一处；**重**：在工具上限内加强证据、反例与矛盾检查。数字是预算，不是凑题配额。
- 只在明确启用访谈后给强度选择；用户不选按标准。中途可随时说「轻点 / 重点 / 先讲解」，讲解时可只问一题。

### 异常处理

- 用户取消 / 跳过 / 超时 → **不重发同一张表单**；退回聊天只补最关键一题。
- 用户想自由聊 → 切换聊天节奏（❓/➡️ 也可不用），不再发表单 / 编号块。

## 三、拷打纪律（relentless）

- **区分含糊与不理解**：不理解先教；理解后仍抽象，才追问依据、约束或例子。
- **矛盾直说**：前后不一致当面指出（包括与记忆 / 画像文件的历史记录冲突），别假装一致。
- **允许暂不决定**：「都行」先区分无偏好、缺信息与委托建议；低风险偏好可给有理由的默认，高影响决策先补信息，不逼二选一，不由此获得执行授权。
- **事实是你的活儿**：能从环境查到的（记忆文件、代码库、文档、上下文）自己查；把查到的事实做成「确认题」（"我看到 X，对吗？"）。
- **问之前先过滤**：这真是该用户拍板的吗？能从上下文 / 合理默认推断的别问；不问低价值问题。
- **深度优先**：完成一个分支再开新的；每轮可留 1 题深挖上一轮最含糊处。
- **访谈不扩大授权**：纯讨论不代做被讨论任务；若原任务已明确授权执行，不额外制造本 skill 的审批门，按宿主流程继续。
- **不做元问题**："我的计划行不行 / 要不要继续"不是提问题材——用收束清单呈现（§四），等确认。

## 四、收束协议（产出「计划书」）

frontier 清空（或用户喊停）时输出**收束清单**：

1. **已锁定**：每条一行（决策 + 一句理由）。
2. **未决 / 搁置**：注明原因 + 风险 + 是否要回来。
3. **下一步**：单一、具体、可执行的动作。（"可执行"标准 = 换个不了解上下文的人照做也能动手。）
4. 记忆写入报告（画像模式）。
5. **确认收束仅确认访谈结论**；执行是否允许，单独按上述审批边界核对，不因确认结论自动开工。
6. 允许记录时，将访谈状态与行动状态分开保存；interview=concluded 不等于 execution=done。

## 五、会话文件（长程拷打）

- 目录：`grill-sessions/<slug>.grill.md`（项目根或该 agent 的记忆目录；跨会话保持同一路径）。
- 允许记录时使用 `templates/session.grill.md`：访谈状态、理解缺口、暂定/已定决策、授权范围、行动结果分别记录，不能用一个 done 混在一起。
- 每轮后仅更新被允许的记录；只读模式在当前对话内维护状态。
- 恢复：用户明确要求「继续 <名字> 的拷打」时先读允许访问的记录，复述状态并重算前沿；没有新的待决问题时不机械追加问卷。旧版单一 done 只作为历史标签保留，若无行动证据则 execution_status=unknown，不能推断已执行或未执行；有证据则如实恢复行动状态。授权仍须结合当前任务、最新限制及宿主实际状态核对，不从旧 done 推断。
- ≤2 轮的短拷打可省文件。

## 六、三种模式

### 用户画像模式
访谈式补全「用户是谁」。仅按既有的用户/宿主记忆规则滚动记录已确认的稳定事实；写入需审阅时保持待审并报告，不声称已应用。骨架和细节分层，保留必要原话；不把方法设置、求讲解、猜测或练习答案写成画像。个人事实不默认写进可能公开的项目规则文件（CLAUDE.md / AGENTS.md 等）。

### 计划·决策模式
对象是判断和取舍；可以解释概念、核实事实和压测假设，不从访谈中派生执行许可。出口是计划或决策清单；只有允许落盘时才写会话文件。

### 知识拷问模式（可选）
先明确范围与难度；一轮一题或一组关联题，批改后针对盲点追问。默认可先补必要概念再考；用户明确要求严格口试、不提示答案时遵守该约定，遇到不懂可暂停或请求提示，不强行教出答案。区分「独立答对」与「讲解后答对」，不把提示后的表现当成已独立掌握。

## Verification（发送前自检）

- [ ] 当前有明确访谈意图？每题的决策依赖与理解前提都满足？
- [ ] 选择题项数合法？推荐确有依据且不是个人事实？没重复写 UI 已附加的 Recommended / Other？
- [ ] 互斥用单选、叠加用多选？选项没写进题干？
- [ ] 没把求讲解当成方案选择或授权、答题当审批、结论确认当执行？原生权限与已有授权均保留？
- [ ] 没问无意义的元问题？超上限已顺序拆表？

反模式：多选做单选 / 互斥开多选；选项塞题干；一轮内问依赖未决；并发多表 / 重发被取消的表；只问不追变问卷；把不懂当敷衍、强迫选择；替用户执行；问"行不行"元问题；表单塞长段落。

## Pitfalls（反模式与示例）

- 不把本协议当成权限执行器；纯提示词不能保证模型绝不误触发或越权。
- 正反例见 `references/example-round.md`；每次变更需核查审批、先教后问和不自动启用三类回归。
- 不把文档规则测试通过，宣称为所有宿主的 UI 或原生审批实测通过。

## 八、外接生态（可选）

- **Spec 工作流**：收束清单可直接升级为 spec——背景 / 目标 → 约束 → 决策记录（D-编号 + 理由）→ 接口 / 架构 → 验收标准 → 开放问题（与 mattpocock 系 `/to-spec`、`/grill-with-docs` 风格兼容）。
- **视觉化**：设计树 / 架构类话题（中途或收束时）可出图（Archify 等交互图工具 / skill）。图是附件，结论仍以收束清单为准。

## 附录 A · Claude Code 细节

- 若有 `AskUserQuestion`，按当前 schema 的 header、选项和多选约束构造，不能假定推荐标签与 Hermes 相同。
- 原生 Plan Mode 的进入/退出及权限确认仍由宿主管理，本 skill 不调用模式切换来代替批准，不擅自更改 `permissionMode` 或 allowed-tools。

## 附录 B · Hermes Agent 细节

- `clarify`：一次最多 5 题，使用 `questions` / `choices` / `multi_select`；取消或跳过不重发整批。
- 记忆分层按运行 profile 和实际限额处理；内置记忆、skill、外部 mem0 的写入门控不能混同。存在待审时如实保留，不用替代通道绕过。
- 会话文件默认放 `<hermes>/memories/grill-sessions/`。
