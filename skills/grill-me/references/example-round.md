# 交互示例与边界回归

这些是规则示例，不是实际执行记录。核心顺序：理解 → 选择；行动还需其独立授权和宿主审批。

## 1. 看不懂时先讲，不继续五连问

已知用户要求多轮梳理笔记方案，主要在当前电脑使用，未授权安装软件。

**不好的问法**：「你要 local-first、云端托管还是 hybrid？顺便授权我安装吗？」

**改写**：「这一题是在决定笔记放哪里，会影响能否跨设备查看，以及数据会去哪里。不是现在就安装。」

用户：「区别没看懂，先教我。」

讲解示例：
- 只保存在电脑：像一本只放在桌上的笔记本，先不涉及同步服务；换设备不会自动出现，备份需另安排。
- 用同步服务：像让设备之间传递副本。能否离线用、是否端到端加密、谁能访问，取决于实际服务，不能一概而论。
- 具体例子：只在一台电脑用，通常可先本地保存；要手机和电脑查看同一份，再比较同步方案及其数据流。

用户：「现在能比较了，可以继续。」

确认能比较后，只恢复当前一题；不把「已讲过」当成「用户已懂」。下面是 Hermes `clarify` 的有效 payload，不是审批 payload：

```json
{
  "questions": [
    {
      "question": "先选保存需求，不进行安装；以你目前主要在这台电脑使用为前提，建议先保持简单。也可用 Other 或聊天要求继续讲解、暂不决定。",
      "choices": [
        "先只在当前电脑保存",
        "需要手机和电脑查看同一份",
        "暂不决定，先看数据流示意"
      ]
    }
  ]
}
```

无原生表单时用同样的白话选项在聊天里问，一轮仍可只问一题。不能因为用户请求讲解，就替他选推荐项。

## 2. 收束确认不是执行批准

- 用户：「选第一个，清单没问题。」
- 正确记录：保存偏好已确认；访谈可收束；安装授权仍未取得。不得写成「已安装」或默认开工。
- 如确需安装，单独交代安装什么、改哪里、数据是否离机，交给宿主原生授权流程。不要把「批准安装」塞回偏好题。
- 用户随后明确说「按刚才的方案，只创建这个目录」时，只授权该目标；不是顺带安装、登录、公开发布或删除的许可。

## 3. 不重复拦截已经授权的工作

- 已有请求：「修改这两份说明文档，不安装、不登录。」
- 用户对一个新增的登录授权题跳过：不授权登录，也不撤销原先文档修改权限。继续允许范围内的工作；若某步确实依赖登录，报告那一个缺口。
- 原生审批拒绝后，不改用另一工具、拆分命令或调低审批设置绕过拒绝。

## 4. 重档也可以先教；不知道不是人格标签

- 用户：「重档，但这个术语不懂。」
- 正确行为：保留重档，先用例子教，再针对理解后的依据和反例追问；不突然问更多术语或强制复述。
- 「先讲解」「猜一个」「还不确定」不进入长期画像。严格口试若事先约定不提示，则暂停或按请求给提示，不能擅自教出答案并记作独立答对。

## 5. 记忆审阅与 skill 修改审阅不被访谈取代

- 事实确认后，仍按宿主和用户原有规则处理记忆；存在写入审阅时报告「待审」，不能声称已写入。
- 不为了绕过内置记忆的待审状态，转写另一个文件或外部记忆提供方；不同存储的门控覆盖不能假定相同。
- 只读讨论不建立会话文件；需要保留时在对话里给出草稿，等相应许可。个人事实不得默认写进可能公开的项目规则。

## 6. 普通请求不进入访谈

「讲一下这个概念」「解释审批模式」「修改 grill-me」以及记忆检索命中的历史访谈记录，都不是新一轮 grill 的启动请求。允许按任务需要读取 skill，但不自动让用户选强度、答问卷。
