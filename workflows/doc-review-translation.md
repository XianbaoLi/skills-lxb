# WF-DOC-REVIEW-TRANSLATION — 中文译文对照复核与验收

## 1. 目的与适用场景

对照原文和中文候选稿，检查遗漏、增译、数学语义偏差、术语不一致和 Markdown 结构问题。复核记录与正文分开保存。

只有用户明确接受当前复核版本后，才能将候选稿提升为正式译文。

## 2. 支持的功能

- 原文与译文的章节、段落和列表覆盖对照。
- 题目条件、数字、单位、选项和图表内容核对。
- 数学逻辑、量词、否定、必要/充分条件和符号核对。
- 专业术语与项目术语表一致性检查。
- Markdown 公式、图片路径、引用和编号检查。
- 将问题按 critical / major / minor 分级并定位。
- 生成修订候选稿。
- 用户批准后的正式版本归档。

## 3. Skill 组成与职责

- **required — mathtranslations**：使用其数学语义、术语一致性和分项复核原则。
- **optional — mineru**：当原文转写或译文问题需要回看 PDF 页面时，使用既有 MinerU 文档定位符读取原页，不重新解析整本材料。

## 4. 输入与输出

**输入**
- <unit>.source.md。
- <unit>.zh-CN.candidate.md。
- 可选：原始 PDF、术语表、前次复核记录。

**输出**
- _work/<document>/translation-review.md：复核记录。
- 按需修订的候选稿。
- 只有在用户明确接受后，才生成 <unit>.zh-CN.md 正式副本。

## 5. 工作流程

1. **确认版本对应关系**：检查原文和候选稿是否来自同一版教材、章节和页码范围，避免拿新原文审查旧译文。
2. **检查内容完整性**：逐段核对标题、正文、定义、定理、证明、例题、习题、条件、选项、图表、脚注和引用。
3. **检查数学语义**：重点核对否定、量词、if/only if、必要与充分、唯一、分别、至少/至多、边界条件、正负号、上下标、单位和公式编号。
4. **检查术语与中文表达**：对照项目术语表，区分技术译法、普通语义和作者自定义用法。
5. **回看原始页面**：当问题可能来自 OCR 时，使用 MinerU 定位或原 PDF 页面核实；不要把原文错误误判为翻译错误。
6. **记录问题**：写入独立复核记录，包含位置、问题类别、严重程度、证据和建议修改。
7. **修订候选稿**：只有在用户要求修订或明确授权当前修订范围时，才修改候选稿；修改后复核受影响内容。
8. **等待明确验收**：复核完成不等于接受。用户明确批准当前候选版本后，才复制/归档为正式译文。

## 6. 状态与验收边界

- candidate：候选稿已生成，尚未完成复核。
- reviewed-candidate：已完成复核，问题及未解决事项已记录；它仍然是候选稿。
- accepted：用户明确批准的具体版本。

不得根据沉默、普通的“继续”、自动检查通过或 Agent 自己的复核结论推断用户接受。

不得覆盖已有正式译文。需要更新时保留旧版本，生成新的候选稿供复核。

## 7. 失败处理

若缺少对应原文、版本不一致或关键来源页面不可用，应说明复核范围受限。不能把未完成的页面级检查描述为完整对照。存在关键问题时保持候选状态，不提升为正式译文。

## 8. 调用示例

- “按 WF-DOC-REVIEW-TRANSLATION 对照英文原文复核 2.4 的候选中文版，先列问题，不要定稿。”
- “修订刚才发现的 major 问题，保留候选状态。”
- “我接受这份已经复核的候选译文，请归档为正式中文版。”
